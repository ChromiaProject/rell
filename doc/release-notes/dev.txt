UNRELEASED NOTES

@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
1. Tools: Language server runs without sun.misc.Unsafe on JDK 25+

The language server's workspace-index cache serialization was migrated from the discontinued Fury 0.4.1 library
to its successor Apache Fory 1.4.0. On JDK 25 and later, Fory (and with it the language server) no longer uses
the deprecated-for-removal sun.misc.Unsafe memory-access API, so the JVM's Unsafe usage warnings disappear and
the server keeps working once the JDK removes the API. On JDK 21-24 behavior is unchanged.

Existing index cache files are in the old format; the server discards and rebuilds them automatically on first
start, so the first startup after upgrading re-indexes the workspace.

2. Tools: Linter inspections run by default, with severities

Inspections now run out of the box. Previously every rule stayed off until it was switched on in .rell_lint, so a
rule nobody enabled reported nothing; the config file now exists to tune inspections or switch them off rather
than to switch them on. Linter findings also carry a severity. Style suggestions surface as weak warnings,
reported to editors as information-level diagnostics, so they are visible without being intrusive, while findings
that point at a likely defect stay full warnings: unused variables, imports outside a module, outer-join
cartesian products and at-expression cardinality misuse.

Two settings remain opt-in: rule_quote_format, because a project has to choose single or double quotes, and
rule_formatter, which gates the formatter rather than an inspection.

Among the inspections that already existed, rule_constant_detection additionally gained a quick-fix rewriting the
reported var to val, for declarators that are not part of a tuple.

Six inspections are new:

  - rule_replace_if_with_when: a chain of if and else-if branches is rewritten as a when block. A plain if/else
    with no else-if is left alone.
  - rule_simplify_boolean_return: an if/else whose branches return only boolean literals collapses to a return of
    the condition itself, in both the statement and the if-expression form; swapped branches give the negated
    condition.
  - rule_redundant_boolean_comparison: reports a comparison against a boolean literal, such as x == true or
    x != false, outside at-expression where-clauses. Diagnostic only - the rule has no type information, and the
    rewrite is unsafe when the operand is a nullable boolean, so no auto-fix is offered.
  - rule_simplify_nullable_if: a null guard of the form "if (x != null) x else y" becomes an elvis expression, and
    "if (x != null) x.f else null" becomes a safe-access expression.
  - rule_prefer_empty: a size() comparison against zero, such as size() == 0 or size() > 0, becomes an empty()
    call or its negation.
  - rule_at_cardinality_misuse: a zero-or-one at-expression followed by a not-null assertion becomes a
    single-cardinality at-expression, auto-fixed when the assertion is the final operation. Indexing a list
    at-expression at zero, and existence checks that materialize a list such as size() == 0 or empty(), are
    reported as diagnostics.

3. Tools: Faster language server startup

Opening a workspace is substantially faster, and no longer blocks the editor. Reported diagnostics are unchanged.

The initialize request used to index the whole workspace before answering, so the editor waited for the entire
scan before it finished connecting. Indexing now runs in the background: the server replies immediately and
reports progress while it works, and diagnostics arrive when the index is ready. Requests that need the index
wait for it rather than answering from a half-built one, so results are unchanged - they just no longer hold up
the handshake.

The indexing itself also got faster, both with an empty index cache and against a warm one, most noticeably on
large projects. Four things account for that.

Each file used to be parsed two or three times and compiled twice. Indexing built a source map for the whole
workspace, then parsed every file again to build its resource, then repeated that for every file with imports.
The repeat pass dates back to when the source map was filled in as the loop went along, so a file indexed early
could not see one indexed later; the map has been built up front since, and the second pass no longer changed
anything. Files are now parsed once and compiled once.

Compilation, which dominates indexing, is spread over a few threads rather than run one file at a time. The
worker count is deliberately a small share of the machine - a quarter of the available processors, at most four -
because the language server shares a machine with an editor and usually a build.

Linter rules are dispatched from a declared table of the syntax nodes each rule handles. Previously the linter
asked, for every rule at every node in the file, whether that rule overrode the matching visit method, and used
the resulting exception as the answer; building those stack traces cost more than running the rules.

Scanning the workspace for Rell files no longer inspects every file it walks past, and skips .git and excluded
folders instead of walking into them and discarding the results. This mostly helps projects carrying a large
node_modules directory.
