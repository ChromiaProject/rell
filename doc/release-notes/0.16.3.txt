RELEASE NOTES 0.16.3 (2026-07-30)

@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
1. Tools: Linter reports if-expression chains for rule_replace_if_with_when

The rule_replace_if_with_when inspection only looked at if statements, so a chain of if and else-if branches in
expression position went unreported:

    val b = if (a == 1) 1 else if (a == 2) 0 else 3;

Such chains are now reported like their statement counterparts, and the quick-fix rewrites them as a when
expression:

    val b = when {
        a == 1 -> 1;
        a == 2 -> 0;
        else -> 3;
    };

A plain if/else expression with no else-if is still left alone.

@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
2. Docs: Generated documentation sites are named after the library they document

The documentation generator titled its output "Rell System Library API Reference", and that same header appeared
on sites generated for libraries other than the system library. A site is now named after what it documents:
"Rell Stdlib" for the system library, the library's own name otherwise. The generator itself is named separately,
in the sidebar version badge ("Rell Docgen 0.16.3") and as the browser title of a site's entry pages
("Rell Stdlib - Rell Docgen"); pages below those read, for example, "crypto - Rell Stdlib".

The system library's overview text, which was silently dropped because it was filed under a name no site used,
is back on the front page. Page URLs are unchanged: the output directory slug stays pinned to the legacy
"Rell System Library" name, so existing links keep working.

@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
3. Tools: Linter quick fixes are titled after the edit they make

A linter quick fix in the language server repeated the diagnostic message as its action title, so the editor
popup showed the problem statement twice ("Variable 'state' is never modified, so it can be declared using
'val'") and never said what applying the action would actually do. Each auto-fix now carries its own title
describing the edit, for example:

    Replace 'var' with 'val'
    Replace 'if' with 'when'

@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
4. Tools: Linter diagnostics underline the offending code instead of one character

The language server published every diagnostic with an empty range, so editors highlighted only the single
character at the issue's position (for example, just the "i" of an if that could be a when). Linter diagnostics
now carry the span of the offending code: expression-level inspections underline the whole reported
expression or name, and statement-level ones underline the keyword the report is about, following the IDE
convention of marking the misused keyword rather than the whole multi-line construct.

Compiler errors and syntax errors still report a single position; widening those requires end positions in
the compiler and is unchanged for now.

@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
5. Tools: Quick fix to disable an inspection globally in .rell_lint

Every linter diagnostic now carries a second quick fix, "Disable '<rule>' in .rell_lint", next to the
existing per-line suppression. Applying it switches the whole rule off for the project: the server sets
"<rule>=false" in the .rell_lint file the linter actually reads (workspace root or up to two parent
directories), creating one at the workspace root with an [*.rell] section when none exists. The edit
runs server-side (workspace/executeCommand), so the linter options reload and the rule's diagnostics
disappear immediately, and repeating the action rewrites the existing assignment instead of appending
duplicates. Formatter diagnostics get the same action for their gating rule_formatter key.

@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
6. Tools: Language server accepts client-chosen settings files (chromiaConfigFiles)

The language server discovered its index roots by scanning workspace folders for files named chromia.yml,
so projects built with an alternate settings file (chr --settings) got no index root:
their compile.source and libs went unapplied and files fell back to single-file indexing. Clients can now
pass the settings files to use as the chromiaConfigFiles initialization option (an array of file URIs).
Registered files are merged with name-based discovery rather than replacing it, each one shadowing the
chromia.yml of its own directory, and every index root reads its Chromia model (rellVersion,
compile.source, libs) from exactly the registered file. Unusable entries are logged and skipped instead of
failing initialize; without the option, discovery behaves as before.

@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
7. Tools: Formatter keeps line breaks written at binary operators

A line break the author put inside an expression only survived in if and while conditions, and only around
and/or. Everywhere else the formatter pulled the operands back onto one line, so

    val b = null
        ?: 1;

reformatted to val b = null ?: 1; on save.

Such a break is now preserved wherever the expression appears, and normalized to the shape the and/or
wrapping already used: the operator moves to the start of the continuation line, indented one level. Both

    val b = null
        ?: 1;

and

    val b = null ?:
        1;

format to the first of the two. An expression the author wrote on one line is untouched, so this stays as is:

    val c = null ?: 3;

@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
8. API: Toolbox modules have a checked public ABI

The toolbox artifacts were excluded from binary compatibility validation, so their whole set of public declarations was
public API by accident and could change from release to release unnoticed. They are now validated like the rest of the
project, each with its own API dump, and the surface has been narrowed to what integrators actually consume:

- ast: the parser and compiler entry points (AntlrRellParser, RellCompilerApi, AstSourceFile,
  RellCompilerFilePath, SyntaxErrorCollector);
- indexer: WorkspaceIndexer, RellResourceFactory, ReferenceIndexer, RellCompilerUtils and the file/symbol
  helpers;
- code-quality: RellFormatter, RellLinter, FormattingStyleLinter and AutoFixer;
- seeder: SeederApi and its parameter builders;
- common: the shared model and value types both of the above and the IDE clients speak in - the Chromia model,
  Position/Range/Location, TextEdit, formatter and linter options, issue types, and the test-data DSL.

Everything else is now internal to its module.

The language server is consumed as a process, so its API is just the two entry points,
and the rest of the module is internal.

Note. This is a breaking change - it may break compilation of code built against those artifacts, because
declarations that used to be public are now internal. It does not affect Rell applications, or IDE clients
that launch the language server as a process.
